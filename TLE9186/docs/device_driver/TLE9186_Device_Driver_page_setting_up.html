Setting up the MOTIX™ TLE9186QV device driver

Integration into software-project

The TLE9186_HAL.c file provides empty function templates for the hardware abstraction layer (HAL) functions required by the TLE9186 device driver. These functions are microcontroller-dependent and must be filled in by the user with the appropriate microcontroller-specific code. To ensure a proper operation it is essential to implement these functions.

Delay function

TLE9186_HAL_Wait_us() implements a delay mechanism to wait for the specified time in microseconds. The microcontroller-specific wait routine must be called within this function. 
void TLE9186_HAL_Wait_us(uint16 u16_wait)
{
  /* Place here the code for waiting */
}

SPI initialization function

TLE9186_HAL_InitSpiPeripheral() initializes the SPI peripheral of the microcontroller. The microcontroller-specific SPI initialization routine must be called within this function. 
void TLE9186_HAL_InitSpiPeripheral(void)
{
  /* Call here microcontroller dependent SPI initialization function */
}

SPI send function

TLE9186_HAL_TransmitTxBuffer() performs an SPI transfer using the microcontroller's SPI peripheral. The data to be transmitted is provided in the u32_txBuffer parameter. The microcontroller-specific SPI transfer routine must be called within this function. 
void TLE9186_HAL_TransmitTxBuffer(uint32 u32_txBuffer)
{
  /* Place here the code to transfer the u32_txBuffer */
}

SPI read function

TLE9186_HAL_ReadRxBuffer() reads the SPI RX buffer of the microcontroller. The microcontroller-specific SPI read function must be called within this function, and the received data should be written into u32_rxBuffer. 
void TLE9186_HAL_ReadRxBuffer(uint32* u32_rxBuffer)
{
  /* Call SPI Read function here and write into u32_rxBuffer */
}

SPI status function

This function retrieves the status of the SPI interface. The microcontroller-specific SPI status function must be called within this function, and the result should be returned. It must return 1 if the SPI interface is ready for transmitting a new frame or reading the received data and 0 if it is still busy processing an earlier command. 
uint8 TLE9186_HAL_SpiStatus(void)
{
  /* Call SPI status function here */
}

INH_N pin initialization function

TLE9186_HAL_Init_INH_N_pin() initializes the GPIO pin that connects to the INH_N pin of the TLE9186. The microcontroller-specific initialization routine for the INH_N pin must be called within this function. 
void TLE9186_HAL_Init_INH_N_pin(void)
{
  /* Initialize the GPIO pin that connects to the INH_N pin */
}

INH_N pin set function

TLE9186_HAL_Set_INH_N_pin() sets the INH_N pin of the TLE9186 to the specified state. The microcontroller-specific function to set the INH_N pin must be called within this function. The u8_state parameter specifies the state to which the INH_N pin should be set (0 = low, 1 = high). 
void TLE9186_HAL_Set_INH_N_pin(uint8 u8_state)
{
  /* Call GPIO function to set INH_N pin to u8_state */
}

ERR_N pin initialization function

TLE9186_HAL_Init_ERR_N_pin() initializes the GPIO pin that connects to the ERR_N pin of the TLE9186. The microcontroller-specific initialization routine for the ERR_N pin must be called within this function. 
void TLE9186_HAL_Init_ERR_N_pin(void)
{
  /* Initialize the GPIO pin that connects to the ERR_N pin */
}

ERR_N pin read function

TLE9186_HAL_Get_ERR_N_pin() reads the state of the ERR_N pin of the TLE9186. The microcontroller-specific function to read the ERR_N pin must be called within this function. The function should return the state of the ERR_N pin (0 = low, 1 = high). 
uint8 TLE9186_HAL_Get_ERR_N_pin(void)
{
  /* Read ERR_N pin and return value */
}

Data types

The TLE9186 device driver uses the the datatypes as defined in the file TLE9186_types.h. It must be ensured that the datatypes are correctly defined in the project.

Initialization and Cyclic update functions

The MOTIX™ TLE9186 device driver provides two main functions for setting up and operating the TLE9186:

  • The TLE9186_ApplLayer_Init() function is responsible for initializing the TLE9186 device driver and the connected TLE9186. This function sets up necessary configurations, prepares the device driver for operation and initializes the register shadow (see here). It should be called during the system initialization phase to ensure that the TLE9186 device driver is properly configured and ready for use.

  • The TLE9186 device driver requires periodic execution of the TLE9186_ApplLayer_deviceDriverCyclicTask() function to maintain the device's status and perform necessary operations. This function should be called at regular intervals to ensure the proper functioning of the device driver. By doing so the following two tasks happen: (1) the set functions, as defined within the function layer, are executed if one was called by the application, (2) the status registers are cyclically read out and the register shadow is updated. During each call of the TLE9186_ApplLayer_deviceDriverCyclicTask() function, either one set function is executed or one status register is read out and the register shadow is updated. The following code snippet demonstrates how these functions can be used in a typical application: 
    #include "TLE9186_ApplLayer.h"

int main(void)
{
    /* Call TLE9186_ApplLayer_Init Function */
    TLE9186_ApplLayer_Init();

    for(;;)
    {
        /* Set functions will be executed within one cycle of the cyclic task */
        TLE9186_ApplLayer_deviceDriverCyclicTask();
    }
}

Example of using the MOTIX™ TLE9186 device driver

The following example demonstrates how to use the TLE9186 device driver to control the TLE9186 half-bridge driver IC. The example sets the watchdog period of the TLE9186 and updates the device status registers. The example assumes that the TLE9186 device driver has been properly integrated into the project. 
#include "TLE9186_ApplLayer.h"

int main(void)
{
    /* Call TLE9186_ApplLayer_Init Function */
    TLE9186_ApplLayer_Init();

    /* Clear bitfield VIO_OV in register SUP_STAT */
    TLE9186_FuncLayer_clear_SUP_STAT_VIO_OV();

    /* Execute clear function */
    TLE9186_ApplLayer_deviceDriverCyclicTask();
    while(TLE9186_ApplLayer_deviceDriverCyclicTask() == TLE9186_DEVICEDRIVER_ERRORLOG_BUSY) {}

    for(;;)
    {
        /* Within every cycle of the cyclic task the TLE9186 status register will be read out and the register shadow updated */
        TLE9186_ApplLayer_deviceDriverCyclicTask();
    }
}
