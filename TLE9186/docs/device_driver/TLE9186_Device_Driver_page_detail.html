In detail: MOTIX™ TLE9186QV device driver

General information

  • Version: 1.0

  • Quality label: Reference software

  • Supported microcontroller: independent

Microcontroller independence

The TLE9186 device driver is designed to be microcontroller-independent, allowing it to be integrated into various microcontroller platforms without modification to the core driver code. This is achieved by abstracting all microcontroller-specific functionality into a separate hardware abstraction layer (HAL). The HAL functions are provided as empty templates in the TLE9186_HAL.c file, which the user must implement with the appropriate microcontroller-specific code. The device driver is microcontroller independent to ensure maximum flexibility and portability across different platforms, making it easier to switch hardware or reuse the driver code in multiple projects.

Software architecture

The TLE9186 device driver's software architecture is structured on six different layers:

  • Application layer

  • Function layer

  • Register layer

  • Service layer

  • Hardware abstraction layer

  • Shadow register

Each layer has specific responsibilities and interacts with the other layers to provide a comprehensive solution for configuring the TLE9186 device. The layers are designed to abstract the complexity of the hardware and provide a structured approach to ensure efficient operation and ease of use.

Application layer

The application layer of the TLE9186 device driver is responsible for initializing and managing the high-level operations of the driver. It serves as the interface between the user application and the lower layers of the driver, ensuring that the TLE9186 device is properly configured and operated.

Key features offered by the application layer:

  • TLE9186_ApplLayer_Init(): Setting up the TLE9186 device driver by configuring necessary parameters and preparing the device for operation

  • TLE9186_ApplLayer_deviceDriverCyclicTask(): Executing user commands (set, clear or get functions) and cyclically updating the status registers of the TLE9186 device in order to keep the shadow register up-to-date. This function should be called at regular intervals to ensure the proper functioning of the device driver. Whenever a set function is called, the cyclic task will execute this function and update the shadow register. If no set function is called, the cyclic task will read out the status registers and update the shadow register.

Function layer

The function layer of the TLE9186 device driver provides an easy-to-use API that enables users to configure and interact with the TLE9186 device. It offers a set of functions to set and get the values of the TLE9186 device registers.

Key features offered by the function layer include:

  • TLE9186_FuncLayer_set_CONFIG_SECURED_FW_CFG(): Set functions for every register to easily configure the TLE9186 device

  • TLE9186_FuncLayer_get_CONFIG_SECURED_FW_CFG(): Get functions for every bitfield within the registers to read the current configuration of the TLE9186 device from the shadow register

Register layer

The register layer of the TLE9186 device driver processes the API calls from the function layer and triggers the generation of the corresponding SPI frames. Additionally, it takes care of updating the register shadow to ensure that the local copy of the device's registers is kept in sync with the actual hardware. Note that for the proper operation of the TLE9186 device driver, the functions of the register layer should not be called directly by the user application.

Service layer

The service layer of the TLE9186 device driver is responsible for the SPI frame generation. It provides the necessary infrastructure to facilitate communication between the higher layers of the device driver and the TLE9186 hardware. The service layer also offers functions to read the ERR_N pin status of the TLE9186 device, allowing the user to monitor the error state of the device. Additionally this layers offers a function to set the INH_N pin of the TLE9186 to a specific state.

  • TLE9186_ServLayer_GetERR_N(): Read the current state of the ERR_N pin of the TLE9186 device

  • TLE9186_ServLayer_SetINH_N(uint8 u8_state): Set the INH_N pin of the TLE9186 device to a specific state

Hardware Abstraction Layer (HAL)

The hardware abstraction layer (HAL) of the TLE9186 device driver is responsible for abstracting microcontroller-specific functionalities, allowing the driver to be microcontroller-independent. The HAL provides empty function templates that must be implemented by the user with the appropriate microcontroller-specific code. Further information is given in the section Integration into software-project.

Register Shadow

The register shadow in the TLE9186 device driver is responsible for maintaining a local copy of the device's registers. This local copy, or shadow, allows the driver to efficiently manage and access the register values without needing to constantly communicate with the hardware. The register shadow is updated in each set function with the corresponding value, ensuring that the local copy reflects the latest changes. Additionally, the cyclic task reads out the status registers from the hardware and updates the corresponding values in the register shadow, keeping it in sync with the actual device status.

Restrictions while working with the device driver

The device driver only supports the in-frame response and there is no error handling in place if the next-frame response configuration is used. Additionally the transmit buffer is constructed in the way that the microcontroller will send out the buffer with MSB first.
